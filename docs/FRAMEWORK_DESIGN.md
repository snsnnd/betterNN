# 框架设计原理、调制机制与改进方案

[返回项目首页](../README.md) · [代码架构](ARCHITECTURE.md) · [实验结论](EXPERIMENTS.md) · [运行指南](REPRODUCING.md)

本文回答三个问题：调制器如何作用于底层网络？这种设计依据什么原理？下一步应该怎样改进？

**第1～5节解释现有实现及其数学性质，第6～8节是建议的新设计和验证方案，尚未实现或验证。** 本文是基于项目源码的机制说明，不是完整的收敛性理论或新架构优越性证明。

## 1. 设计目标：把计算内容与计算控制部分分开

普通循环网络通过固定参数的状态转移处理序列：

```text
h_(t+1) = f(h_t, x_t; W)
```

这里“固定参数”指一次推理期间通常不更新权重，不代表模型训练时不能学习 W。

本项目额外产生随上下文变化的控制量：

```text
控制量 u_t = Controller(可观察元数据, 状态摘要)
h_(t+1) = f(h_t, x_t; W, u_t)
```

希望把以下职责显式分开：

1. **Write**：哪些输入值得写入？
2. **Route**：已有信息从哪里传到哪里？
3. **Hold**：哪些状态现在应更新，哪些应保留？
4. **Readout**：如何把最终状态转成答案？
5. **Selector（第七轮）**：当前任务使用哪些候选节点？

与储备池计算的联系在于早期可冻结随机循环底层；与门控RNN的联系在于乘法门及状态插值；与条件计算的联系在于根据上下文改变有效运算。它们是理解本设计的已有概念，不构成项目新颖性证明。

### “上层/下层”不代表两个自主智能体

第一轮的 `upper` 和 `lower` 都是小型前馈 MLP。它们在每个时间步按当前输入计算一次门值；`lower` 能观察底层状态摘要。代码没有实现高层规划器对低层控制器发布符号指令、两层分别设定目标或两个独立强化学习过程。

因此，这里的层次首先是**控制作用位置不同**，而不是已经实现了完整的分层智能系统。

## 2. 调制器如何“传递”给底层？

调制器输出普通 PyTorch 张量，底层更新公式直接读取这些张量，并进行逐元素乘法、块级加权和状态插值。没有消息队列或额外通信协议；门值本身就是数学接口。

### 2.1 Write：先缩放输入，再投影进底层

以第七轮为例：

```text
p_t = sigmoid(Write(meta_t))             # [batch, 2]
input_t = (x_t ⊙ p_t) B                 # [batch, n]
```

`⊙` 是逐元素乘法，`B` 是固定输入投影。若某步 `x_t=[2,-1]`、`p_t=[0.9,0.1]`，投影前的输入变为 `[1.8,-0.1]`。第一路大部分通过，第二路被抑制。

它控制的是写入幅度，不自动执行跳过计算。第七轮 `B` 只将第一路写到来源A、第二路写到来源B，门值不能将它们直接改写到任意目的节点。

### 2.2 Route：改变有效连接强度

第一轮每个源块只有一个门值，同行向量约定下：

```text
W_bar = W ⊙ topology_mask
recurrent_t = (h_t ⊙ expand(g_t)) W_bar
W_eff(t) = diag(expand(g_t)) W_bar
```

同一源块发往所有目标的连接一起变强或变弱。这个接口不能独立决定“从A去X开放、从A去Y关闭”。

第四轮局部路由分支以及后续相应模型改用源块×目标块的16个门。令 `s,d` 为源和目标角色，`i,j` 为角色内节点：

```text
g_t = sigmoid(Route(meta_t, pool(h_t)))  # [batch, 4, 4]
rec_t[d,j] = c * Σ_s Σ_i h_t[s,i] * W_bar[s,i,d,j] * g_t[s,d]
```

第七轮 `dense` 的 `c=1`，`topk` 的 `c=sqrt(n/64)`。每个样本可有不同门值。

例如，若 `W_bar[A_i,X_j]=0.6`，门值为0.8时，该边乘门后的权重为0.48；门值为0.1时为0.06。这里未计入第七轮 Top-K 的额外全局缩放。

**Route 的作用边界：**

- 不能打开拓扑掩码已经置零的边。
- 正的 sigmoid 门本身不翻转权重符号。
- 同一源—目标块内的边共享门值，不是每条边独立控制。
- 改变 `W_eff(t)` 不等于永久更新存储的 W；若 W 可训练，它的长期变化来自优化器。

### 2.3 Hold：控制新旧状态的混合

第七轮每个角色一个更新系数：

```text
a_t = 0.2 * sigmoid(Hold(meta_t))         # [batch, 4]
candidate_t = tanh(rec_t + input_t)
h_next = (1-a_t) ⊙ h_t + a_t ⊙ candidate_t
```

若旧状态为0.7，候选状态为−0.3：

- `a=0.02` 时新状态为 `0.98*0.7 + 0.02*(-0.3) = 0.68`。
- `a=0.2` 时新状态为 `0.8*0.7 + 0.2*(-0.3) = 0.50`。

这里0.2用于展示更新幅度上界；学习门在有限实数 logit 下通常严格小于0.2。名字虽叫保持门，代码输出 `a` 实际上是**更新率**，真正保留旧值的系数是 `1-a`。

第一轮 `a` 固定0.2；第二轮可学习保持门为每样本一个标量；后期局部模块模型为每角色一个标量。它们不是完全相同的控制精度。

### 2.4 Selector：状态更新后施加节点掩码

第七轮另有：

```text
h_next = h_next ⊙ selection(task)
```

Top-K 在每个角色中选16个节点，共64个。它根据任务身份查可学习分数表，选择在当前任务的整个序列内固定；不是由当前输入内容每步重新选择。

前向掩码是0/1，反向用 straight-through 代理：

```text
soft = 16 * softmax(selector[task])
selection = hard_top16 + soft - stop_gradient(soft)
```

这使选择分数能够接收梯度，但该梯度是硬选择的代理，不是离散 Top-K 的精确导数。

### 2.5 第七轮每一步完整流程

```text
元数据 ──→ Write ──→ 输入门 p ──→ (输入 x ⊙ p) B ─────┐
                                                     │
元数据＋状态摘要 ──→ Route ──→ 块门 g ──→ 循环传递 ───┼→ tanh → 候选状态
                                                     │             │
元数据 ──→ Hold ──→ 更新率 a ─────────────────────────────→ 新旧状态插值
任务ID ──→ Selector ──→ 节点掩码 ─────────────────────────→ 掩码后的新状态
                                                                   │
                                                      下一步 / 最终局部读出
```

相同元数据和输入可以产生不同底层轨迹，因为 Route 还依赖已有状态；不同任务也可以在同一个 W 上形成不同有效动力学。

## 3. 控制器能看到什么？

| 实现 | Write / Hold | Route | 其他信息路径 |
|---|---|---|---|
| 第1轮 | Write看任务与相对时间；无学习Hold | 任务＋4块状态均值 | 任务经固定C直接进入候选状态 |
| 第2轮主门控模型 | 任务、时间、外部有效标记 | 任务＋4块状态均值 | 同一元数据经固定C进入底层；部分对照限制Write观测 |
| 第4轮局部路由 | 已到达规则及时间等元数据 | 元数据＋4角色状态均值；有规则盲对照 | 数值A/B只写入来源角色 |
| 第7轮 | 7维元数据，不直接看数值A/B | 7维元数据＋4角色状态摘要 | 任务身份从t=0可见，规则从t=4可见；无早期C投影路径 |

训练标签通过损失函数使用，不作为这些控制器的前向输入。状态摘要可能间接携带数值信息；“不直接看原始输入”不等于“完全没有内容信息”。第四轮 Salience 的匹配辅助监督属于单独明确设置的训练分支。

## 4. 调制器如何学会控制？

核心训练链路是：

```text
门控参数 → p/g/a → 底层状态序列 → 读出 → 任务损失
                                                   │
                    优化器更新 ← 反向传播梯度 ←─────┘
```

若控制器参数为 `θ`，最终状态为 `h_T`，可概括为：

```text
dL/dθ = (dL/dh_T) (dh_T/dθ)
```

`dh_T/dθ` 包含门值对当前状态的影响，以及影响沿后续时间步传播的路径。PyTorch自动微分完成链式求导。

### 冻结 W 与截断梯度不是同一件事

- **冻结 W**：不更新 W，但仍可用 W 把状态梯度传回控制器。线性映射的权重是常量，也有对输入的导数。
- **`h.detach()`**：保留状态数值，切断此前状态计算图与后续损失之间的梯度路径。
- **`no_grad()`**：若将整个底层前向放进去，会阻断所包围运算的自动微分，不能替代“仅冻结 W”。

第七轮在训练时 `t=5,10,15` 前 detach 状态，损失只在终点计算。早期输入没有来自终点的直接状态链梯度；共享控制器及W仍会因后面时间步获得的梯度而更新。不能据此称为生物局部学习。

### 状态记忆与参数记忆也不同

每次前向调用的 `h` 都从零开始；当前 batch 的激活状态不会跨样本永久保留。第六、七轮所谓持续学习，保留的是阶段之间的模型参数，再测量旧任务能力。

所以“Hold能保住序列中的状态”并不意味着“Hold能防止训练下一个任务时改坏权重”。两种遗忘需要分别研究。

## 5. 哪些理论性质成立，哪些只是设想？

### 5.1 有界状态是可直接说明的

`tanh` 候选状态在 `[-1,1]` 内，旧状态从零开始，更新系数在 `[0,1]` 内，凸组合仍在 `[-1,1]` 内。第七轮再乘前向0/1掩码，仍保持此界。

这是对状态数值范围的说明，**不保证读出logit有同样界、不保证信息不丢失、不保证梯度稳定，也不保证状态收敛到有用解**。

### 5.2 小更新率提供较慢的直接衰减路径

只考虑 `candidate=0`、固定更新率a的简化情况：

```text
h_(t+k) = (1-a)^k h_t
半衰期 k_half = ln(0.5) / ln(1-a)
```

`a=0.1` 时半衰期约6.6步，`a=0.02` 时约34.3步。这解释了慢更新为何可能帮助保留状态，但真实候选状态包含输入、循环反馈和动态门，不能把这些数字当作实际模型的记忆容量。

### 5.3 初始谱范数0.9不等于整体收缩

W初始化谱范数为0.9，但完整转移还包含状态依赖Route。求状态雅可比时要计入门值随状态变化的导数；后期W可学习，第七轮还有Top-K缩放。因此不能仅凭初始化范数推出全局收敛或长期稳定记忆。

### 5.4 小控制器是一种结构约束，不自动带来省算力

只输出少数门值，可以限制每步有效变换的自由度，并形成适合某些任务的归纳偏置。但模型仍保存底层矩阵，冻结底层时也可能需要经其运算反传，门控还引入额外开销。

第七轮主要循环运算仍随批量、序列长度和 `n²` 增长；把节点乘零不使稠密 `einsum` 自动成为64节点计算。

### 5.5 实验支持的是有条件的机制收益

| 设想 | 现有证据 |
|---|---|
| 固定随机底层可被控制器有效利用 | 第1轮调制器＋读出92.55%，支持简单任务；读出冻结组55.87% |
| 选择写入与保持状态应分开 | 第2轮长干扰加入保持门改善，支持当前任务 |
| 动态Route始终必要 | 不支持；旧任务静态替换影响很小，局部目的任务中收益更明确 |
| 冻结底层足够解决后期任务 | 不支持；第5轮正常更新W明显优于冻结W |
| 短梯度窗口可以学习 | 第5轮当前配置支持，但不等于局部学习算法 |
| 冻结底层可以防遗忘 | 第6轮不支持；共享控制器和读出仍可能改变 |
| Top-K分区由训练自发涌现 | 第7轮不足以支持；任务专属表在初始化就形成分区 |

## 6. 我的改进原则：先解决已观察到的瓶颈

以下为建议，不是现有系统功能。首要目标建议设为：**在固定训练与存储预算下，提高多任务获取和保留，并定位收益来源。** 暂不把“替代大模型”作为下一轮实验的直接验收目标。

### 6.1 首先分清选择机制的收益

沿用第七轮数据与任务顺序，先选一个固定规模（例如256节点）比较：

1. dense；
2. 固定随机Top-K，每任务选定支持集后冻结；
3. 可学习Top-K，从同一初始支持集出发。

第2、3组保持完全一致的活跃预算、缩放、状态摘要归一化、W/读出/控制器初始化和优化设置，只改变选择表是否更新。dense只是参考；**可学习选择的核心归因比较是第2与第3组**。

若学习组并未可靠超过固定随机组，应先将结果解释为隔离和容量收益，而不是智能路由。此时更简单的固定选择甚至可能更值得采用。

**第八轮已完成该实验（N=256、5 种子）：learned − fixed 的 final_mean 为 −0.66 ± 9.13 个百分点，正种子 2/5，选择器明显移动但未带来稳定收益。结论支持稀疏隔离解释，因此当前优先项已转向 6.2 的遗忘定位。** 结果见 [flow_mvp_v8/REPORT.md](../flow_mvp_v8/REPORT.md)。

### 6.2 先定位遗忘，再添加保护机制

在各任务独立可学的前提下，对共同起点分别试验：冻结或保护W、控制器、读出，以及固定预算回放。每种保护都同时观察新任务学习是否被妨碍。

**第九轮已完成该实验（N=256、5 种子）：固定预算 replay 的最终平均 69.46%、遗忘 16.84 个百分点，均为最好；冻结控制器崩溃到 34.99%；只保护读出不足；freeze_W 与只更新控制器略优于 all，但不稳定。** 结果见 [flow_mvp_v9/REPORT.md](../flow_mvp_v9/REPORT.md)。

**第十轮已建立干净基线**：新任务集 A'B'C'D' 单独学习约 99.8%，验证选择 65 轮/阶段；顺序 CL 基线 acquisition 97.37%、最终平均 80.80%、遗忘 22.10 个百分点。**第十一轮在该基线上给出结论：每步 12.5% 的 replay 已把遗忘压到约 1 个百分点；冻结 W 没有再增加稳定性，反而损失约 4 个百分点最终成绩（配对 1/15 为正）。** **第十二轮证明这不等同于“任何架构加 replay 都行”：容量匹配的 GRU（67k）在 25% replay 时遗忘仍有 5.72 个百分点，Flow 只需约 6.7% 就达到 ≤3pp，vanilla RNN 在该预算下根本未学会。同等历史预算下 Flow 的 memory efficiency 明显更高。** 见 [flow_mvp_v11/REPORT.md](../flow_mvp_v11/REPORT.md) 与 [flow_mvp_v12/REPORT.md](../flow_mvp_v12/REPORT.md)。

固定小回放缓冲可作为实用基线，但必须记录总存储量和总更新次数；替换当前任务batch的一部分与额外追加训练不是同一预算。后者不能直接用于声称算法更高效。

按任务独立读出或独立控制器可以作为定位干扰的诊断组，但它们增加任务专属容量和身份依赖，应单列报告。

### 6.3 改善控制器的可观察信息

第七轮每角色仅保留一个有符号均值。正负激活可能相互抵消，不同状态也可能有相同均值。建议逐项比较：

- 现有均值摘要；
- 均值＋均方根/幅度统计；
- 固定维数的可学习状态投影。

这可能改善Route的决策信息，但也可能只是增加容量；需提供参数量接近的控制器对照。若进一步让控制器看输入编码，所有基线应获得相同可观察信息，并保留经底层状态读出的约束。

### 6.4 避免过早把通道关死

针对第2、3轮观察到的通道近乎关闭，先记录门logit、门值分布、梯度范数及逐任务准确率，再比较非饱和初始化或短暂的软门预热。

`sigmoid`导数为 `p(1-p)`，靠近0或1时较小，提供了可能的优化解释，但现有相关性不能单独确认失败原因。永久给门加较大下限会放行干扰，也应作为有代价的消融，而非默认修复。

### 6.5 可训练底层与稳定适应分两个阶段

不建议一开始就坚持随机底层永久冻结。更合理的候选是：先联合训练底层、编码器、控制器和读出，建立可用表示；再研究持续学习时哪些参数值得保护。

一种待验证方案是：

```text
W = W_shared + U V
W_bar = W ⊙ topology_mask
```

其中 `U∈R^(n×r)`、`V∈R^(r×n)`。离线学习共享底层，适应时冻结或较慢更新共享部分，优先更新小适配器和控制器。

低秩适配只限制可训练更新的形式，不保证不遗忘；共享控制器、读出和适配器仍会互相干扰。给每个任务新增适配器会增长存储，并依赖适配器选择机制。固定掩码和块门也使整体算子不再是简单低秩乘法，不能由 `UV` 形式直接推导推理加速。

## 7. 更长期的候选框架

完成以上单因素验证后，再考虑组合成下列框架：

```text
输入/指令 → 可训练编码器 → 内容特征 ──→ 受控写入 → 模块化循环状态 → 读出
                              │                     │
                              └→ 小型控制器 ← 丰富但限宽的状态摘要
                                    │
                           写入 / 路由 / 更新 / 模块选择

训练：共享表示学习 → 受限参数适应＋固定预算回放/保护（分别验证）
```

### 内容条件控制，而不是仅查任务编号

可先保留任务ID进行机制实验，再在新协议中让控制器从指令、上下文和历史状态推断所需计算。不直接提供任意任务编号，并不意味着删除所有区分任务的信息：若同一可见输入在不同隐藏任务下要求互相矛盾的输出，任务本身不可辨识。

训练和测试时都应只使用当时可观察的信息，不能让选择器读取未来规则。

### 多时间尺度记忆

可将状态分成快、慢组，分别初始化不同更新率，再允许学习。对照应保持节点总数和训练预算相同，比较单时间尺度与多时间尺度的长度泛化。这是前向记忆设计，与共享W和适配器的参数更新速度是两个独立问题。

### 真正稀疏执行

第七轮同任务序列的支持集固定，推理时有机会仅收集选中节点对应的W子矩阵、B列和读出权重，执行活跃子图。需要保持每角色配额、门控、归一化和缩放一致，并验证输出数值与原稠密前向相符。

训练不能直接假定等价：当前straight-through选择器依赖被硬掩码遮住的候选值产生代理梯度。若只计算选中节点，会改变未选节点的学习信号。因此可先实现并测量稀疏推理，再把稀疏训练作为独立设计问题。

小矩阵、动态索引和kernel启动开销可能抵消理论节省，必须实际测量端到端延迟、吞吐及内存。逻辑活跃数只是一项机制统计。

## 8. 建议的验收顺序

| 阶段 | 要回答的问题 | 最小对照与指标 |
|---|---|---|
| A：机制归因 | 学习选择是否优于天然随机分区？ | 固定/学习Top-K配对；获取、最终平均、遗忘、支持集变化（第八轮已完成：未见稳定优势） |
| B：保留能力 | 旧知识被哪些共享部分破坏？ | W/控制器/读出保护及固定预算回放；新旧任务同时评估（第九轮：replay 最有效，冻结控制器最伤；第十一轮：clean benchmark 上 freeze_W 无叠加收益） |
| C：观测和优化 | 是否因摘要不足或门饱和导致失败？ | 摘要消融、初始化消融；门值/梯度轨迹、逐任务表现 |
| D：实际效率 | 限制活跃节点是否真正省计算？ | 稠密/活跃子图等输出推理；吞吐、延迟、峰值内存 |
| E：适用范围 | 能否从人工规则走向一般序列？ | 更长依赖、更多顺序、可辨识但无显式ID任务，再到真实数据 |

每阶段先独立验证，不同时叠加所有机制。建议沿用至少5种子，并在持续学习研究中增加多个预先固定的任务顺序；保存阶段模型、优化器状态、完整配置及逐任务指标。超参数用验证集选择，最终测试集用于固定方案评估。

在当前可解析的小任务上，可预先约定单任务学习门槛，例如独立任务准确率95%；达不到时，先分析拟合和优化，不将较小遗忘自动当成优势。该门槛是建议的工程验收值，不是理论标准，更不适用于所有真实任务。
