# 第八轮计划：Top-K 机制归因

## 要回答的问题

第七轮 Top-K 相对 dense 的提升，究竟来自**可学习的选择**，还是仅仅来自**每任务天然使用不同节点造成的稀疏隔离**？

三种假说：

- **H1**：可学习选择优于固定随机选择，选择器学到了有用的任务—节点分配。
- **H2**：两者接近；收益主要来自稀疏隔离（每任务有独立随机支持集，减少互相干扰）。
- **H0**：两者接近且都优于 dense；稀疏隔离是主因，学习不是。

## 预先固定的设计

- 规模 N=256，每角色 Top-K=16，共 64 个逻辑活跃节点。
- 种子 11/22/33/44/55，共 5 个配对种子。
- 任务 A→B→C→D 顺序持续学习，每任务 30 轮、512 训练样本、batch 128、5 步 BPTT、无回放。
- 三组：`dense`（全节点）、`fixed_topk`（每任务随机支持集，初始化后冻结）、`learned_topk`（直通代理梯度学习选择器）。

严格配对要求：

1. 同一 seed 下三组的 W、B、mask、write、hold、route、headX/Y、selector 初始化逐位相同。
2. 训练数据、验证数据、测试数据、批顺序、更新次数、优化器超参数完全一致。
3. `fixed_topk` 与 `learned_topk` 前向数值相同，唯一差别是选择器是否接收梯度。

## 记录指标

- acquisition（四任务刚学完平均）、final_mean（最终四任务平均）
- forgetting、BWT
- 每任务逐轮验证曲线与 `epochs_to_90`（新任务学习速度）
- task overlap：选择 Jaccard 初始/最终、激活重叠、SI 选择性
- selector change：支持集 IoU（初始→最终）、选择器参数 L2 位移
- 路由余弦、每秒数等运行信息

## 预先约定的判定规则

令 `gap = mean(learned_topk - fixed_topk)`，按种子配对计算：

- `gap >= +5` 个百分点且至少 4/5 个种子为正 → 支持 H1，下一步研究动态选择与功能分区。
- `gap <= -5` 个百分点且至多 1/5 个种子为正 → 学习选择更差，先检查优化与梯度问题。
- 其余情况 → 支持 H2/H0，当前收益主要来自稀疏隔离；下一步转参数保护 / replay / consolidation，而不是继续复杂化 Router。

该阈值为预先约定的工程判定，不是统计显著性检验。

## 边界

- dense 与 topk 的活跃预算不同（256 vs 64），且 topk 另有缩放与状态摘要归一差异；dense 只作为参照，核心归因比较是 fixed 与 learned。
- 只有 5 个种子、一个任务顺序、单一合成任务，结论限于本协议。
- GPU 运行与第七轮 CPU 存档不承诺逐位一致；配对比较在第八轮内部成立。
