# 第十二轮：Flow vs GRU vs RNN 的等预算 replay 曲线

## 问题

第十一轮证明低比例 replay 几乎消除遗忘，但 replay 是通用方法。本轮检验真正有价值的问题：

> **达到同样的遗忘水平，Flow 架构需要多少 replay？与容量匹配的 GRU / 普通 RNN 相比是否更省历史信息？**

如果三者曲线接近，说明持续学习收益主要来自 replay，而不是架构；如果 Flow 在更低 replay 比例下达到同样的遗忘，才是架构的 memory efficiency 优势。

## 协议

- 任务集：第十轮 A'B'C'D' benchmark，65 轮/阶段，每步固定 128 样本。
- 顺序：o0=[A',B',C',D']，o1=[D',C',B',A']，o2=[B',D',A',C']。
- replay 比例：0 / 6.25% / 12.5% / 25%（每步回放 0/8/16/32 个旧样本，固定 32 样本/任务）。
- 种子 11/22/33/44/55，共 3 架构 × 4 比例 × 3 顺序 × 5 种子 = 180 条流。
- 架构与容量：
  - `flow`：N=256，约 66,244 可训练参数，5 步 BPTT（既有实现）。
  - `gru`：输入 9（x+meta），隐藏 144，约 67,250 参数，完整 BPTT。
  - `rnn`：tanh RNN，输入 9，隐藏 252，约 66,530 参数，完整 BPTT。
- 所有架构共享同一数据、批顺序、replay 采样生成器与优化超参数；GRU/RNN 与 Flow 的差异只在模型与梯度路径。

## 指标与判定

- 每组：acquisition、final_mean、forgetting、BWT（合并三个顺序）。
- 核心派生指标：**达到遗忘 ≤ {5, 3, 1} 个百分点所需的最小 replay 比例**（在相邻比例间线性插值）。
- 基线核对：`flow` 路径应与第十一轮 `all` 组 60 条流矩阵逐位一致。

## 边界

- 架构默认设置不同（Flow 5 步窗口，RNN/GRU 完整 BPTT），不是严格等梯度预算；但样本、更新次数、优化器和 replay 完全一致。
- 只有 3 个顺序、5 个种子、单一规模与合成任务。
- GRU/RNN 隐藏宽度按参数量匹配，未做各架构独立调参。
